    Every published build passes all of these first. Each was written in the same change as the defect it prevents, and each has a deliberate break that proves it can fail.

    Routines and who is in control

    Day-to-day upkeep is done by routines; a person keeps control. Each routine has a tier: 0 Observe reads and reports; 1 Maintain changes derived or reference data only after every check passes, in one commit that names the routine, so it is one revert to undo; 2 Propose prepares a pull request or an issue for a person; 3 Person only is never automated. Every Monday the digest routine opens one issue listing what each routine did and what needs a person. To stop every tier 1 routine changing anything, set the repository variable AUTOMATION to off.

    Never automated

    • Change repository settings, rulesets, secrets or the kill switch.
    • Delete a branch, tag, release, issue or file a person made.
    • Send anything outside the repository (pull requests or issues elsewhere, email, posts).
    • Change the profile, its codelists, the requirements, the registers or any page content written by a person.
    • Claim conformance, endorsement or approval.
    • Merge a pull request.

    Trials

    New ideas are tried as trials: each states what it is trying to learn, what it may touch, how success is measured, when to stop, and an end date at most 90 days away. Each has its own kill switch, a repository variable TRIAL_ followed by its name, and AUTOMATION stops them all. The build fails if a trial runs past its end date, so every trial is either made a routine by a person or stopped.

    No trials are running.

    Near misses

    Anyone, person or routine, reports a near miss or a surprise with the occurrence issue form. No blame: the report asks what happened and what would have stopped it, never who. A routine that stops itself (kill switch, failed gate, abort rule) says so in the digest. Every occurrence closes with either a check that would have caught it (as for a defect) or a recorded reason why none is needed. Report one with the occurrence form.

    The same pattern runs across the connected portals; see ADR 0017.
