    What's changed

    What's changed from the xGov MEM

    Updated 1 section on this page is new or updated since 1.2.0-rc.1 (2026-11-06). Everything that changed

    Every property of the xGov MEM maps to the profile, so existing records convert automatically. 21 of the 22 open backlog items are resolved here; the rest need the owner. 56 properties are new, mostly from that backlog.

    In summary

    • Built on the DCAT 3 Recommendation instead of a working draft, and aligned with DCAT-AP 3.0.1 so records harvest into European tools.
    • Every bug in the backlog is fixed: the contact point definition, the distribution range, the missing security classification IRI, the wrong example publisher and the title case examples.
    • New requirements from the working group are in: geographic coverage, time period, schema, personal data, sensitive data, reference data and who can see a record.
    • Critical data assets get their own mandatory properties, from the April 2026 guidance.
    • Codelists are linked data, mapped to EU vocabularies. Themes use the data.gov.uk topics.
    • Contact points prefer a contact form and never name a person.
    • Release management: semantic versions, a change request form, release assets and a release gate.

    The backlog

    Read from the xGov MEM repository on 2026-11-06 V: 99 issues and pull requests, of which 22 issues and 12 pull requests were open. Contributors are not named.

    Every open xGov MEM issue (22), and how it was dealt with

    #86Major overhaul tracking issue for the metadata exchange model and siteResolvedThis repository is the overhaul. Its six workstreams map to this repository: dependencies and infrastructure (one build script, no generator chain to keep patched), schema fixes (every model bug below), documentation and site (the portal), new requirements (spatial, temporal, schema, personal and sensitive data), governance and release management (versioning, change requests, the release gate) and community (issue forms and Discussions). The tracking issue in co-cddo can be closed with a link here once the owners agree.What's changed from the xGov MEM, Design and governance

    #76Title examples in alternative title don't follow the rules for titlesResolvedExamples now follow the sentence case rule they illustrate, and a check fails the build if an example title is in title case.Alternative title, Title, C-EX-02
    #72Distribution is incorrectly configured as an IRI or CURIEResolvedA distribution can now be described in the same record or referred to by its IRI. The SHACL shape and JSON Schema both accept either.Distribution
    #71The contact point definition is the same as the email definitionResolvedContact point is now defined as the contact as a whole.     #69The OS postcodes example names the wrong publisherResolvedThe example is rebuilt from the public record and credits Ordnance Survey as publisher and creator.example
    #63Codelist pages don't link out to external vocabulariesResolvedThe portal is generated by this repository's own script, so every concept links to its scheme and to the matching EU concept. The LinkML limitation no longer applies.Codelists
    #60Add usage notes to access rightsResolvedUsage notes for each value, the difference from licence and security classification, and a rights statement for anything not open.Access rights, Access rights
    #49Recommend a taxonomy for theme valuesResolvedThe 14 data.gov.uk topics are the theme list, as the issue proposed, each with a readable identifier rather than a search address, and mapped to the EU data themes. The cross-government taxonomy can replace it when published.Theme

    #30What to do with assets that don't have a modified dateResolvedLast updated is recommended, not mandatory, and must never be invented. The created and release dates cover the rest.Last updated

    #11Include schemas in the documentation siteResolvedJSON Schema, SHACL, JSON-LD context, LinkML, SKOS codelists, CSV and examples in Turtle and JSON-LD are all downloadable, with a DCAT description of them.Downloads and API

    #4Capture the schema of the underlying datasetResolvedConforms to (dct:conformsTo), as DCAT recommends and the issue proposed, with guidance by format and a link to the Tabular data standard. Mandatory for critical data assets.Conforms to
    #3Capture the reference data used and its resolutionResolved, provisionalA provisional "reference data used" property that links to the classification or code list (for example age bands) and its version.Reference data used

    Alignment with DCAT-AP

    The UK profile keeps every mandatory property of DCAT-AP 3.0.1V, so any record that conforms here is a valid DCAT-AP record for those properties. It adds UK requirements on top.
