    Access address dcat:accessURL

    A web address that gives access to the distribution, such as a landing page, a download page or an API.

    IRI
    dcat:accessURL
    Value
    url
    Why it matters
    The one address every distribution must have, so people can always get to it.
    Not to be confused with
    Download address, which is a direct link to a file.
    Since the xGov MEM
    New. Missing from the xGov MEM. Mandatory in DCAT-AP; added so UK records harvest into European catalogues.
    Also known as
    Data Marketplace: accessURL; schema.org: url K
    Used on
    Distribution

    Access rights dct:accessRights

    Who can get the data, and on what terms.

    IRI
    dct:accessRights
    Value
    concept, from Access rights
    Why it matters
    Tells people at once whether they can have the data and how to ask for it.
    Not to be confused with
    Licence (what you may do with it once you have it) and security classification (how it must be protected).
    How to fill it in
    Choose open when anyone can have it without asking; commercial when it is available for a fee or under commercial terms; internal when it is only available to the public sector, or to named organisations, under an agreement. Say what the restriction is in the rights statement when it is not open.
    Example
    ukcl:access-rights/open
    Since the xGov MEM
    Codelist mapped. Same three values (OPEN, COMMERCIAL, INTERNAL), now SKOS concepts mapped to the EU access-right vocabulary used by DCAT-AP. Usage notes added (issue 60).
    Also known as
    2026 guidance: accessRights; Data Marketplace: accessRights
    Backlog
    #60 #5
    Used on
    Dataset, Data service, Distribution

    Algorithm spdx:algorithm

    The algorithm used to calculate the checksum, from the SPDX list.

    IRI
    spdx:algorithm
    Value
    concept, from Checksum algorithms
    Why it matters
    Lets people check a file with the same algorithm, and lets owners find files still checked with weak algorithms.
    How to fill it in
    Use SHA-256 or stronger. For files that must stay trustworthy for many years, prefer SHA-384, SHA-512 or SHA3. MD5 and SHA-1 are accepted so old records still conform, but the validator warns about them (rule Q-01): they are broken against deliberate tampering today. Quantum computers do not break these hash functions in the way they break public-key cryptography; see the quantum-ready page.
    Example
    spdx:checksumAlgorithm_sha256
    Since the xGov MEM
    New
    Used on
    Checksum

    Applicable legislation dcatap:applicableLegislation

    Legislation that requires, governs or permits the publication or sharing of the resource.

    IRI
    dcatap:applicableLegislation
    Value
    iri
    Why it matters
    Shows the legal basis at once, and lets catalogues group resources by the law that applies, as DCAT-AP 3 does.
    Not to be confused with
    Rights statement (what a person must do to get the data) and conforms to (a technical standard the data follows).
    How to fill it in
    Give the legislation.gov.uk address of the Act or regulation, for example https://www.legislation.gov.uk/ukpga/2017/30 for the Digital Economy Act 2017. For EU law, give its European Legislation Identifier (ELI) address. Give one value per law.
    Example
    https://www.legislation.gov.uk/ukpga/2017/30
    Since the xGov MEM
    New
    Used on
    Dataset, Data service

    Conforms to dct:conformsTo

    A standard, specification or schema the resource follows.

    IRI
    dct:conformsTo
    Value
    iri
    Why it matters
    Tells technical users how the data is structured before they get it, and lets tools check it.
    How to fill it in
    For a dataset, link to its schema (for example a CSV on the Web metadata file, a JSON Schema or an XML schema) or the data standard it follows. Tabular data should follow the Tabular data standard. For a data service, link to the standard the interface follows (for example OpenAPI 3.1 or OGC API - Features), not the data.
    Example
    https://www.gov.uk/government/publications/recommended-open-standards-for-government/tabular-data-standard

    Also known as
    2026 guidance: conformsTo; schema.org: conformsTo (dct) K

    Connection security Provisional dcatuk:transportSecurity

    The kind of key exchange the service's endpoint uses to protect data in transit, classical or post-quantum.

    IRI
    dcatuk:transportSecurity
    Value
    concept, from Connection security
    Why it matters
    Turns the catalogue into part of the cryptographic inventory the NCSC asks organisations to build by 2028, so services still using only classical key exchange can be found and migrated.
    How to fill it in
    Say what the endpoint negotiates today. Choose hybrid when it offers a post-quantum key exchange (ML-KEM, FIPS 203) alongside a classical one. Update it when the service changes. This describes the service; it does not make it secure.
    Example
    ukcl:transport-security/tls13-classical
    Since the xGov MEM
    New
    Used on
    Data service

    Contact point dcat:contactPoint

    Where to ask questions about the resource or give feedback on it.

    IRI
    dcat:contactPoint
    Value
    object: Contact point
    Why it matters
    Gives people a route to the team that can answer questions about the resource.
    Not to be confused with
    Publisher (an organisation) and the contact point's own properties (form, email, telephone).
    How to fill it in
    Give a team, never a named person. A contact form is the preferred route: it keeps addresses private and can be moved when teams change. An address for a shared team mailbox is allowed; a personal address is not.
    Since the xGov MEM
    Definition fixed. The definition was a copy of the email definition (issue 71). It now describes the contact point as a whole.
    Also known as
    Data Marketplace: contactPoint; schema.org: contactPoint (via publisher) K
    Backlog
    #71 #15
    Used on
    Dataset, Data service, Dataset series, Catalogue

    Identifier dct:identifier

    The main identifier of the resource in the publisher's own catalogue.

    IRI
    dct:identifier
    Value
    literal
    Why it matters
    Lets systems tell records apart, avoid duplicates and link to the same resource across catalogues.
    Not to be confused with
    The record's web address (its IRI), which should also be stable, and other identifiers (use "other identifier").
    How to fill it in
    Use an identifier that will not change, even if the resource moves or the organisation is reorganised. Opaque, non-sequential identifiers are best. Do not reuse an identifier for a different resource.
    Example
    2dfb82b4-741a-4b93-807e-11abb4bb0875
    Since the xGov MEM
    Range relaxed. Was restricted to an IRI or CURIE. A plain literal now, as in DCAT, so local catalogue identifiers can be used; the record IRI carries the web identity.
    Also known as
    2026 guidance: identifier; schema.org: identifier K
    Used on
    Dataset, Data service, Distribution, Organisation
