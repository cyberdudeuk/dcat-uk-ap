    Last updated dct:modified

    The date the content of the resource last changed.

    Obligation
    Mandatory
    Cardinality
    1
    IRI
    dct:modified
    Value
    date
    Why it matters
    Helps people judge whether the data is current enough for their use.
    Not to be confused with
    The date the metadata record changed, which belongs on the catalogue record.
    How to fill it in
    Give it whenever you know it. If you do not know it, leave it out rather than using the date the record was harvested: a false date is worse than none (issue 30).
    Example
    2026-08-01
    Since the xGov MEM
    Obligation changed. Mandatory in the xGov MEM, but many sources do not provide it (issue 30). Recommended now, and never to be invented.
    Also known as
    schema.org: dateModified K

    Recommended properties

    Conforms to dct:conformsTo

    A standard, specification or schema the resource follows.

    Obligation
    Recommended
    Cardinality
    0..n
    IRI
    dct:conformsTo
    Value
    iri
    Why it matters
    Tells technical users how the data is structured before they get it, and lets tools check it.
    How to fill it in
    For a dataset, link to its schema (for example a CSV on the Web metadata file, a JSON Schema or an XML schema) or the data standard it follows. Tabular data should follow the Tabular data standard. For a data service, link to the standard the interface follows (for example OpenAPI 3.1 or OGC API - Features), not the data.
    Example
    https://www.gov.uk/government/publications/recommended-open-standards-for-government/tabular-data-standard
    Since the xGov MEM
    New
    Also known as
    2026 guidance: conformsTo; schema.org: conformsTo (dct) K
    Backlog

    Security classification dcatuk:securityClassificationNew

    The classification under the Government Security Classifications Policy that the data itself carries.

    Obligation
    Optional
    Cardinality
    0..1
    IRI
    dcatuk:securityClassification
    Value
    concept, from Security classification
    Why it matters
    Stops data being shared with people or systems that cannot protect it, and keeps catalogues in scope.
    Not to be confused with
    Access rights (who may have it). On a catalogue record the same property gives the classification of the record itself, which is usually OFFICIAL even when the data is not (RQ-03).
    How to fill it in
    Most public sector data is OFFICIAL. Use the OFFICIAL-SENSITIVE marking where it applies. Records about SECRET or TOP SECRET data must not be put in an OFFICIAL catalogue; the Data Asset Management Policy covers OFFICIAL assets only.
    Example
    ukcl:security-classification/official
    Since the xGov MEM
    Property IRI fixed. Had no property IRI at all, so it could not be exchanged as linked data. NOT_APPLICABLE is withdrawn: public sector data always has a classification.
    Also known as
    2026 guidance: securityClassification; Data Marketplace: securityClassification

    Missing value dcatuk:missingValueNew

    A property this record leaves empty on purpose, and why.

    Obligation
    Optional
    Cardinality
    0..n
    IRI
    dcatuk:missingValue
    Value
    object: Missing value
    Why it matters
    Lets a strict harvester tell a value that is unknown, withheld or not applicable from one that was simply forgotten, without guessing.
    Not to be confused with
    Leaving the property out, which says nothing about why it is empty.
    How to fill it in
    Use it for recommended or optional properties you cannot give. It never satisfies a mandatory property, which must have a value; the validator warns if you try (rule Q-02). Say withheld only when a value exists but cannot be published in this record.
    Example
    {"missingProperty": "dct:temporal", "missingReason": "unknown"}
    Since the xGov MEM
    New

    Source record dct:sourceNew

    The original metadata record this record was harvested or converted from.

    Obligation
    Optional
    Cardinality
    0..1
    IRI
    dct:source
    Value
    iri
    Why it matters
    Lets anyone go back to the authoritative description, and stops a harvested copy from being mistaken for the original.
    Not to be confused with
    Describes (the dataset or service), and the dataset's own provenance, which is about the data rather than the record.
    How to fill it in
    Give the web address of the record in the catalogue it came from. DCAT-AP uses the same property for source metadata (RQ-08).
    Example
    https://example.org/catalogue/record/road-casualties
    Since the xGov MEM
    New

    Property added or changed on the way dcatuk:enrichedPropertyNew

    A property whose value was added or changed by the harvester or converter, rather than taken from the source record.

    Obligation
    Optional
    Cardinality
    0..n
    IRI
    dcatuk:enrichedProperty
    Value
    iri
    Why it matters
    Shows which values the original publisher did not give, so nobody is held accountable for, or misled by, values someone else added.
    How to fill it in
    Give the property's prefixed name, such as dcat:theme, once for each property the harvester filled or changed.
    Example
    dcat:theme
