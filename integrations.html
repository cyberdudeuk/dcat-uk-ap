    Integrations and connectors

    Updated 3 sections on this page are new or updated since 1.2.0-rc.1 (2026-11-06). Everything that changed

    Any catalogue, metadata repository, data platform or data space connector can speak DCAT-AP-UK. Most already speak DCAT or a model the weaver converts. This page shows how to connect, gives suppliers everything they need to prove conformance, and lists products by how close they are today.

    Ways to connect

    Publish and be harvested

    Any catalogue

    Publish one DCAT catalogue file (Turtle or JSON-LD) at a stable address. Harvesters such as data.gov.uk, the National Data Library or EU portals collect it on a schedule.

    How

    Check in your pipeline

    Teams who keep metadata in a repository

    Run the GitHub Action or the command-line checker on every change; it fails the build on any error and annotates the line.

    How

    Embed the validator

    Product teams

    Ship validator.js inside your product: the same rules, quality score, converters and exports the portal uses, with no network calls.

    How

    Run the reference API

    Platform teams

    A small HTTP server with check, score, weave and profile endpoints, described in OpenAPI. Run it next to your catalogue.

    How

    Convert at the edge

    Products on another model

    Weave CKAN, DCAT-US, schema.org, Dublin Core, DDI or xGov MEM records to DCAT-AP-UK on export, and back on import.

    How

    Connect an AI assistant

    Any team using AI tools

    The MCP server lets assistants look up the profile and check, score, convert and export records.

    How

    Offer data in a data space

    Data space participants

    Use the data space extension so connectors can read each offer and its ODRL policy from the catalogue.

    Supplier conformance kitUpdated

    • Every worked example, which must be accepted, and every deliberate break, which must be rejected with the rule named.
    • The same for every sector extension the product supports.
    • A manifest (conformance-kit.json) listing each case, its file and the expected outcome, for automated test runs.
    • Round trip: import each example, export it, and check the export still conforms and keeps every property.

    Download the kit manifest 56 cases: 20 to accept and 36 to reject. Files are in downloads/conformance/.

    Command line and pipelinesUpdated

    # check records (JSON, JSON arrays or CSV in the template columns)
python3 -I tools/build.py
node integrations/cli/validate.js --ext health records/*.json

# convert CKAN records at the edge, and annotate errors in GitHub
node integrations/cli/validate.js --from ckan --format github export.json

    In GitHub Actions:

    - uses: actions/checkout@v4
- uses: cyberdudeuk/dcat-ap-uk@main   # pin to a release tag or commit
  with:
    files: metadata/*.json
    extensions: geospatial

    Embed the validator

    One file, no dependencies, no network calls; it runs in browsers and in Node.

    const V = require('./validator.js');          // site_src/validator.js, MIT
const P = require('./profile.json');           // downloads/profile.json
const result = V.validate(P, record);          // errors and warnings, by rule
const level  = V.conformance(P, record);       // level 1 to 3
const out    = V.weave(P, 'ckan', 'ukap', pkg); // convert, with the threads

    Reference API

    A small HTTP server with check, score, weave and profile endpoints, described in OpenAPI 3.1. It is a reference to run yourself, not a hosted service; it accepts at most 1 MiB and stores nothing.

    node integrations/http/server.js --port 8787
curl -s -X POST --data @record.json http://127.0.0.1:8787/validate?ext=health

    Conformance claims and badges

    A supplier can claim conformance for a product version, level and set of extensions with the conformance claim form. A claim is self-assessed and public; it is listed once the evidence (a link to the kit's results) is checked. A claim is not an endorsement.
