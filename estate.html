    Estate

    The estate: four portals

    Four open portals for data in the public sector, each with its own owner, purpose, audience and status. They link to each other and share keys; they do not merge or copy each other's content. The comparison was made by reading each portal's repository on 6 November 2026. "Not seen" means it was not found in that review and may exist.

    Proposed standard, not endorsed

    Not sure where to start? The estate compass suggests a route across all four. DCAT-AP-UK is its South bearing: the ground everything else stands on, because nothing can be found, governed or improved until it is described.

    The architecture it implements

    The Future pan-UK metadata architecture (DCAT-AP-UK founding specification and architecture blueprint)P sets out DCAT-AP-UK as the shared record for the UK’s data ecosystems. This portal is a working implementation of that record: the profile, its sector extensions, validators, migration from the xGov MEM and the adoption toolkit. The repository is private, so its contents are not reproduced here; reconciling the two is on the open register (O-14).

    What each gains from the others

    • DCAT-AP-UK to DAM capability playbooks: The cataloguing playbook can cite DCAT-AP-UK as the agreed field set instead of its own proposed crosswalk, once the profile is endorsed.
    • DCAT-AP-UK to Public Sector Data Quality Commons: The Metadata Weaver can read profile.json and the JSON-LD context, so "describe once" outputs a record that conforms.
    • DCAT-AP-UK to GitHub Repos Asset Catalogue: The catalogue's DCAT JSON-LD feeds can declare conformance to the profile and use its organisation identifiers.
    • Public Sector Data Quality Commons to DCAT-AP-UK: Records link quality reports through dqv:hasQualityAnnotation; the Commons supplies the reports.
    • DAM capability playbooks to DCAT-AP-UK: The critical data asset rules come from the policy the playbooks explain; their roles name who records what.
    • GitHub Repos Asset Catalogue to DCAT-AP-UK: The organisations list (register R3, GOV.UK slugs) is reused from the catalogue rather than copied by hand.

    Journeys across portals

    • Record a critical data asset: DAM capability playbooks (What the policy requires) then DCAT-AP-UK (Build the record with critical data asset switched on) then Public Sector Data Quality Commons (Check the quality of the data) then DAM capability playbooks (Report and sustain)
    • Buy or replace a catalogue tool: Public Sector Data Quality Commons (Compare products and lock-in) then DCAT-AP-UK (Ask suppliers to pass the test records) then GitHub Repos Asset Catalogue (See who already runs the tool)
    • Build a discovery service: GitHub Repos Asset Catalogue (Find catalogue code that already exists) then DCAT-AP-UK (Map every source to the shared record) then Public Sector Data Quality Commons (Score metadata quality)

    Disclaimers and transparency

    Not an official GOV.UK service or policy, and not endorsed by the Data Standards Authority. Facts carry source labels: V verified, K background knowledge, P supplied pack, U unconfirmed.
