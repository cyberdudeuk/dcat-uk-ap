    Knowledge

    Updated 2 sections on this page are new or updated since 1.2.0-rc.1 (2026-11-06). Everything that changed

    The words, structure and connections behind the profile: a glossary, a thesaurus of other words people use, the taxonomy of classes and codelists, the few terms the profile adds, and a graph of how it all connects.

    Glossary

    Application profile
    A standard with the choices made for one community: which properties are mandatory, recommended or optional, and which controlled lists to use.
    Catalogue
    A curated collection of metadata records about datasets and data services.
    Catalogue record
    The entry in a catalogue about one dataset or service, with its own dates.
    Codelist
    A fixed list of values to choose from, so the same thing is always recorded the same way.
    Conditional
    Mandatory only when a stated condition applies, for example a rights statement when access is not open.
    Conformance
    A record conforms when it meets every mandatory and conditional rule. Recommended properties are not needed to conform.
    Critical data asset
    A data asset shared with another public sector organisation to deliver an essential purpose or process. In scope of the Data Asset Management Policy.
    Crosswalk
    A table showing how the terms of one model match the terms of another.
    CURIE
    A short form of an IRI, such as dct:title, using a declared prefix.
    Data Asset Management Policy
    The 2026 policy that requires government departments and their arm's-length bodies to manage metadata about critical data assets in their catalogues and report it to GDS.
    Data service
    A set of operations, usually an API, that gives access to data.
    Data sharing agreement
    A written agreement between organisations setting out what data is shared, why, and under what law.
    Dataset
    A collection of data, published or curated by one organisation, available in one or more forms.
    Dataset series
    Datasets published separately that share a subject and method, such as each census.
    DCAT
    The W3C standard for describing datasets and data services in catalogues on the web. Version 3 became a W3C Recommendation on 22 August 2024.
    DCAT-AP
    The European application profile of DCAT, maintained by SEMIC. Version 3.0.1 was published on 27 October 2025.
    Distribution
    One form in which a dataset can be got, such as a CSV file or an API response.
    GSS code
    A nine-character code for a statistical or administrative area in the UK, maintained by the Office for National Statistics.
    Harvesting
    One service collecting metadata records from many catalogues, so they can be searched together.
    IRI
    A web address used as a globally unique name for a thing.
    JSON Schema
    A standard for describing what a JSON document must look like, so tools can check it.
    JSON-LD
    A way of writing linked data as JSON. With the profile's context, a compact JSON record becomes RDF.
    LinkML
    A modelling language the xGov MEM was written in. This profile still publishes a LinkML version.
    Metadata
    Information that describes data: what it is, who holds it, how to get it and what you may do with it.
    Metadata Implementation Working Group
    The cross-government group that turned the Metadata Requirements Specification into the xGov MEM.
    National Data Library
    The UK programme to make public sector data easier to find and use. data.gov.uk is becoming part of it.
    Obligation
    Whether a property is mandatory, recommended, optional or conditional in a record.
    Persistent identifier
    An identifier that keeps working when the thing it names moves. w3id.org provides redirects for this.
    Personal data
    Information about an identifiable living person (UK GDPR).
    Provenance code
    The label on a fact in this portal: V verified at the source, K background knowledge, P from a supplied pack, U unconfirmed.
    RDF
    The W3C data model DCAT is built on: statements of subject, property and value, using web identifiers.
    Security classification
    The level of protection information needs under the Government Security Classifications Policy: OFFICIAL, SECRET or TOP SECRET.
    SHACL
    The W3C language for rules that RDF data must meet. The profile's rules are published as SHACL shapes.
    SKOS
    The W3C standard for publishing codelists, thesauri and taxonomies on the web.
    Special category data
    Personal data that needs extra protection, such as health, ethnicity or religion (UK GDPR Article 9).
    Turtle
    A compact, readable way of writing RDF.
    xGov MEM
    The UK metadata model this profile evolves. Endorsed for implementation by the Data Standards Authority Steering Board.

    Everything else is reused from DCAT, Dublin Core, vCard, ADMS, PROV, SPDX, DQV and schema.org. Only these are new, under the proposed namespace https://w3id.org/dcat-ap-uk/ns#. Download the definitions.

    • dcatuk:securityClassification: The classification under the Government Security Classifications Policy that the data itself carries.
    • dcatuk:personalData: Whether the data contains information about identifiable living people, and in what form.
    • dcatuk:sensitiveData: Whether the data contains information that needs extra care beyond being personal, such as special category data.
    • dcatuk:metadataAudience: Who is allowed to see the metadata record itself. (provisional)
    • dcatuk:referenceData: A code list, classification or set of groupings the data uses, such as age bands or a geography. (provisional)
    • dcatuk:criticalDataAsset: Whether the resource is a critical data asset under the Data Asset Management Policy.
    • dcatuk:jurisdiction: Every country or territory where the data is stored or processed, or to which it is sent. (provisional)
    • dcatuk:transferMechanism: The basis under UK GDPR on which personal data in the resource may be sent outside the UK. (provisional)
    • dcatuk:transportSecurity: The kind of key exchange the service's endpoint uses to protect data in transit, classical or post-quantum. (provisional)
    • dcatuk:missingValue: A property this record leaves empty on purpose, and why.
    • dcatuk:missingProperty: The property that has no value, as its prefixed name or full IRI.
    • dcatuk:missingReason: The reason the property has no value, from a list based on the GML and INSPIRE nil reasons.
    • dcatuk:enrichedProperty: A property whose value was added or changed by the harvester or converter, rather than taken from the source record.
