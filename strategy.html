    Strategy

    How it fits the strategy

    Updated 1 section on this page is new or updated since 1.2.0-rc.1 (2026-11-06). Everything that changed

    The profile is one small part of a bigger plan: making public sector data easy to find and use across the UK. This page shows which parts of that plan it serves, and where its limits are.

    What it serves

    What each strategy needs, and how the profile serves it
    Strategy or policyHow the profile serves it
    Future pan-UK metadata architecture (DCAT-AP-UK founding specification and architecture blueprint)PThe architecture names DCAT-AP-UK as the shared record across UK data ecosystems, with domain profiles, validation and migration from the xGov MEM. This portal implements that record, its sector extensions, its validators and its migration tools, so the architecture has something working to test against.
    A roadmap for modern digital government 2025 to 2030VPlatforms to share and use data need records that mean the same thing in every catalogue. The profile is that shared meaning.
    National Data Library: progress update, January 2026VA single trusted gateway to public sector data needs findable, consistent, honest records. The profile gives harvestable records with the access, licence and quality signals users need.
    Data asset management policy in governmentVDepartments must manage and report metadata about critical data assets. The critical data asset switch makes the guidance's attributes mandatory in the same record the catalogue already holds, so returns can be built, not retyped.
    Recording metadata to describe critical data assetsVEvery attribute the guidance lists is crosswalked to a property. Where the guidance is inconsistent (created and dateCreated), the profile picks one term and records the alias.
    Metadata Based Discovery of Data Sets and Sources (draft pattern, version 1.0)VThe pattern needs a canonical metadata record that harvesters map to. The profile, with its shapes and JSON Schema, is proposed as that record, so each adapter maps to one target.
    Cross-government data sharing principles (draft)VPrinciple 6 asks for common standards for sharing. The profile is one, reusing DCAT and DCAT-AP rather than inventing.
    Guidelines and best practices for making government datasets ready for AIVMetadata quality is a pillar. Conforms to, time and place covered, quality annotation and the schema.org crosswalk help machines as well as people judge a dataset.

    A pan-UK public data infrastructure

    Read from the top, people find data; read from the bottom, bodies keep their own data and describe it once. The layers are the author’s model, drawn from the sources below K.

    1. People and systems: Researchers, service teams, policy makers and the public find, judge and ask for data.
    2. Gateways and returns: The National Data Library, the Data Marketplace and Data Asset Management returns read the same records.
    3. Harvest and discovery: Discovery services collect records, map them to the shared record and make them searchable.
    4. The shared record (this profile): DCAT-AP-UK: one meaning for every record, with shapes to check it.
    5. Catalogues: Each body describes its assets once, in its own catalogue.
    6. Data held by public bodies: Datasets and services stay with the bodies accountable for them (federate first).

    England-only rules are not presented as UK-wide. Check each nation’s position before relying on it K.

    Limits

    • The profile describes data; it does not move it, grant access to it or check its quality.
    • The Data Asset Management Policy names no metadata standard. Using this profile for returns needs a decision by the owning team.
    • The strategic roadmap for public sector data had not been published when this was written. When it is, check this page against it.
    • Mappings marked K need a specialist review before endorsement.

    Related profiles and models

    • schema.org Dataset: Used by search engines. The portal shows the schema.org term for each property where one exists. K
    • Croissant (MLCommons): Metadata for machine learning datasets, built on schema.org. Relevant to AI-ready data. K
    • GeoDCAT-AP: The geospatial extension of DCAT-AP, aligned with INSPIRE and ISO 19115. K
    • StatDCAT-AP: For statistical data; a version 3 is being revised. K
