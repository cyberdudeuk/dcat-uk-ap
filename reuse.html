    Reuse across government

    New This page is new since 1.2.0-rc.1 (2026-11-06). Everything that changed

    Most of what a catalogue team needs already exists somewhere in government: an endorsed standard, a vocabulary, a register, a catalogue product or a toolkit. This page lists the public pieces that fit with DCAT-AP-UK, what each is for, and how to use it alongside the profile. Nothing here is endorsed by this portal; check each one with its owner before relying on it.

    What government code actually uses

    Counts are repositories with at least one file that uses the standard or names the product, from public GitHub only. A low count does not mean a standard is little used: much metadata lives in catalogue products, not in public code. From the GitHub Repos Asset Catalogue P.

    OpenAPI and JSON Schema dominate, which is why DCAT-AP-UK publishes a JSON Schema and turns an OpenAPI description into a data service record. Linked data standards (DCAT, SKOS, PROV-O, SHACL) are rarer in public code, so the portal's tools hide RDF unless you ask for it. CKAN is by far the most common catalogue product, which is why the CKAN crosswalk and the ckanext-dcat route come first in the adoption toolkit.

    The 2023 Data Marketplace records, checked against DCAT-AP-UK

    The Data Marketplace API repository publishes example DCAT records in Turtle for its triplestore: 4 datasets, 3 data services and 7 distributions. They were checked against the DCAT-AP-UK SHACL shapes with pySHACL. Two of the nine files did not parse, because they use a prefix they never declare. Source: the Data Marketplace API repository V.

    Every problem is one the weaver and the xGov MEM conversion already fix or flag: text turned into codelist values, organisations turned into links, a missing classification asked for. None needs a change to the profile. This is the migration the adoption toolkit describes, measured on real government records.

    How this list was made

    The GitHub Repos Asset Catalogue lists 12,251 UK public-sector repositories (from the cross-government open source scraper, read on 8 October 2026). Its descriptions and topics were searched for metadata, catalogue, vocabulary, schema, register, standard, quality, sharing and discovery terms (517 matches). Its standards scan, which reads files in the repositories, was used for the evidence below. The closest 24 repositories were then cloned and read on 6 November 2026, to confirm what each holds, its licence and when it last changed. Archived repositories are left out. Repositories linked to national security work are left out of this public page.
